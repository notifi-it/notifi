# notifi

notifi is a push-notification relay for people who live in a terminal. You create a
send key, `curl` a title and message to `notifi.it/send`, and the alert lands on your
iPhone and Mac. The backend is a single Cloudflare Worker over a D1 database; the app
is a zero-dependency SwiftUI client for iOS 17+ and macOS 14+. There are no accounts,
no sign-in, and no device linking — the device holds the only private key, message
content is sealed to that key at ingest so the server cannot read it afterwards, and
the server keeps messages for seven days. It is a relay, not a mailbox.

The full design is in [docs/PLAN.md](docs/PLAN.md); manual verification steps are in
[docs/VERIFYING.md](docs/VERIFYING.md). This project has **no automated tests and no
code comments** by decision — constraints live in the plan, verification is by hand.

## Quickstart (Worker dev loop)

```bash
pnpm install
make migrate     # apply migrations to the local dev D1
make dev         # wrangler dev — local Worker + local D1
```

`make dev` runs the default (dev) wrangler environment. Deploys:

```bash
make deploy-dev  # wrangler deploy            → notifi-api-dev on workers.dev
make deploy      # wrangler deploy --env production → notifi-api on notifi.it
```

Local `wrangler dev` cannot reach APNs sandbox without the real `.p8`; put dev copies
of the secrets in `apps/api/.dev.vars` (gitignored) for a working local push loop.

### The two-environment / APNs split (read before debugging any push)

There are two wrangler environments, two D1 databases, and **two APNs hosts**. This is
the single most common way APNs silently breaks — treat it as load-bearing:

| | dev (default) | production (`--env production`) |
|---|---|---|
| Worker | `notifi-api-dev` | `notifi-api` |
| D1 | `notifi-dev` | `notifi-prod` |
| Route | `workers.dev` | `notifi.it` |
| `APNS_HOST` | `api.sandbox.push.apple.com` | `api.push.apple.com` |
| App build | Xcode debug builds | TestFlight + App Store builds |

**A TestFlight build gets a *production* APNs token, so it must point at the production
Worker.** Only local Xcode debug builds use dev/sandbox. A sandbox token sent to the
production host (or vice versa) is `400 BadDeviceToken` — 95% of "pushes stopped."

## Secrets

Worker secrets are set per environment with `wrangler secret put` and are **never
committed** (local dev copies go in the gitignored `apps/api/.dev.vars`):

- `APNS_TEAM_ID`
- `APNS_KEY_ID`
- `APNS_PRIVATE_KEY` — the `.p8` PEM contents
- `ENCRYPTION_KEY` — 64 hex chars (32 bytes)

Non-secret vars live in `wrangler.toml`: `APNS_HOST`, `APNS_TOPIC` (the shared bundle
id `it.notifi.app`).

### CI secrets (GitHub repository / environment secrets)

- `api.yml` — `CLOUDFLARE_API_TOKEN`. Production deploy is gated behind the
  `production` GitHub Environment (manual approval).
- `infra.yml` — `CLOUDFLARE_API_TOKEN`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`
  (the last two authenticate the R2-backed Terraform state; see `infra/README.md`).
- `app.yml` TestFlight lane (tag pushes `v*` only) — `DISTRIBUTION_CERT_P12` (base64),
  `DISTRIBUTION_CERT_PASSWORD`, `PROVISIONING_PROFILES` (base64 tar of the profiles),
  `ASC_API_KEY_P8` (base64 App Store Connect API key), `ASC_KEY_ID`, `ASC_ISSUER_ID`.
  Upload uses `xcodebuild -exportArchive` with the App Store Connect API key — never
  `altool` (Apple discontinued it in 2023). PR builds run unsigned
  (`CODE_SIGNING_ALLOWED=NO`) and do not upload.

## Three things to be honest about

- **Image URLs are fetched by the recipient's device.** If a message carries an
  `image`, the phone downloads it — so a sender who controls that image server can
  learn the device's IP address and online state. Only send images from hosts you'd
  hand your IP to.
- **Message ids are a global counter.** A `202 {id}` response reveals system-wide send
  volume, not just yours. Don't read anything private into the number, and know that
  it leaks the platform's total throughput to anyone who sends.
- **A send key in a public web page is public.** Anyone who can see it can use or
  exhaust it. Treat keys embedded anywhere public as burnt: scope them narrowly and
  revoke freely (revocation is instant — the next `/send` returns `401`).

## Support playbook

- **"Works in debug, not TestFlight."** A sandbox token was sent to the production
  host or vice versa. Check the environment table above first, always.
- **"Notifications stopped."** Focus mode or a revoked permission. The Settings health
  check row and the Send Test Notification button exist precisely for this.
- **"New phone, my scripts now return 401."** By design — the key died with the old
  device, and there is no migration. The loud `401` (not a polite `200`) is what tells
  a monitoring loop something changed. The app also detects the restored-phone state
  and explains this on first launch.
