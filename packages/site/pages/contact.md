# Contact notifi

> One person answers everything here, in English, usually within a few working days. Pick whichever route fits what you are writing about.

## Email

[`hello@notifi.it`](mailto:hello@notifi.it) reaches the person who builds notifi. Use it for anything that does not belong in a public issue: press and partnership questions, App Store or licensing questions, or a problem you would rather not describe in the open.

There is no phone line and no support desk. notifi is free, has no accounts to lock you out of, and holds nothing about you that a support agent could look up, so email is the whole of it.

## Bugs and feature requests

Open an issue at [github.com/notifi-it/notifi/issues](https://github.com/notifi-it/notifi/issues). A bug report travels faster in the open, and the code it concerns is right there. Include the platform and app version, what you sent, and what arrived — never include a send key, and never paste one into an issue: a key is a credential, and anything in a public issue is public forever. Revoke it in the app if you have already posted one.

## Security disclosure

Email [`hello@notifi.it`](mailto:hello@notifi.it) with the details rather than opening a public issue, and give a reasonable window to fix it before publishing. The cryptography, the API and both apps are open source, so a report can point straight at a line. Probing the live service beyond what a proof of concept needs is out of bounds — the [terms](/terms) cover that.

## Privacy and data requests

The [privacy policy](/privacy) describes what is stored, which is deliberately almost nothing: there is no account, no email address and no name attached to a device. Without your device's public key there is no way to tell which records are yours, so deleting the app is both the faster and the more complete route. If you would still like a request raised, email [`hello@notifi.it`](mailto:hello@notifi.it) or open an issue.
